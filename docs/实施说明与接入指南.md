# 合作项目本次实现与后续接入指南

本次基于合作仓库 `main` 的 `7a4540a559f9e17fac462844dac15dbd89fe042e` 开发，分支为 `codex/complete-proposal-20261121`。沿用港股固定 CSV 和现有单 Agent 工具循环，没有引入个人双 Agent 方案。原 `main` 的历史及数据文件保持不变。

本次完成了图表与结构化结果、保留筛选条件的追问、会话切换与恢复、运行进度、数值展示校验、日志计时、独立计算对照、无工具 Baseline 和离线评估流程。按用户安排，真实模型地址暂不配置；真实任务成功率、语言解释质量、集群链路与 API 响应时间仍须接入后验证。

## 1 模型地址填在哪里

### TACC Qwen

**文件方式：修改 `agent/server-url.txt`，仅放一行实际地址，例如 `http://实际计算节点:8000/v1`。** 模型服务重启后地址可能变化，要重新填写。现有课程适配器使用 `qwen3.8-27b`；如课程模型名变化，修改 `agent/qwen_client.py` 中 payload 的 `model` 字段，并在评估记录中同步记录。

也支持环境变量和参数：

```bash
export QWEN_BASE_URL='http://实际计算节点:8000/v1'
python3 agent/chat_agent.py --provider qwen --base-url "$QWEN_BASE_URL" --prompt '分析 0700.HK 的财务指标和历史走势'
python3 agent/local_web.py --provider qwen --base-url "$QWEN_BASE_URL"
```

上述本地启动方式要求运行机器能访问该地址。课程内部地址不能默认从笔记本直接访问。按原来的课程部署，在 `agent/` 下执行 `bash submit-web.sh`，再在已配置课程 SDK 的本机执行 `python3 web_bridge.py CHAT_JOB_ID`。服务作业和聊天作业都需运行。新依赖 `evidence.py`、`session_store.py` 已加入提交脚本。

### DeepSeek 本地网页

```bash
export DEEPSEEK_API_KEY='在本机填写密钥'
# 可选：export DEEPSEEK_MODEL='账户支持的模型名'
python3 agent/local_web.py --provider deepseek
```

PowerShell 使用 `$env:DEEPSEEK_API_KEY='在本机填写密钥'`。密钥仅从环境变量读取，不写进源码或会话文件。根目录 `.env.example` 是配置示例，程序不会自动加载它。

浏览器打开启动命令打印的 `http://127.0.0.1:8765/`。`--port` 可换端口，`--data-dir` 可指定私有会话目录。

## 2 现在不接模型也能查看界面

在仓库根目录执行：

```bash
python3 agent/demo_web.py
```

这是**显著标注的脚本化离线演示**，没有 LLM。支持页面的三个示例按钮、基础股票概览和排名 Top-K 追问；它使用真实固定 CSV 做计算，但回复选择是测试脚本。不要用它衡量模型自然语言能力。默认会话文件在临时目录，进程结束清理；如需保留，可指定 `--data-dir`。

## 3 每项功能如何实现

| 功能 | 实现位置 | 行为与边界 |
|---|---|---|
| 财务数值和排名展示 | `agent/evidence.py` | 后端从实际工具结果生成数值、单位、期间、来源和贡献分解，模型不重新计算 |
| 数值解释检查 | `validate_answer` | 解释正文禁止数字和日期，仅允许已验证 ticker、指定指标名称和存在的证据 ID；不合格时反馈修正 |
| 有限循环和降级 | `ChatAgent.ask` | 最多 12 步；已有合法计算而解释仍失败时，只展示工具结果并明确标为降级；无合法结果则报错 |
| 历史图表 | `analysis_tools.py`、`chat.html` | 全部价格与均线由 Python 产生；浏览器 SVG 绘图、开关图线和悬停读数；缺失值保留断点 |
| 排名贡献 | `rank_stocks` | 显式返回各指标加权贡献，和等于总分；仍使用筛选后候选集分位数 |
| 追问状态 | `ChatAgent.state` | 保留最近排名结果 ID 与顺序、筛选参数、权重、窗口、关注对象 |
| 继承筛选条件 | `reuse_previous=true` | 只覆盖显式提供的参数；`filters={}` 清空条件，显式 weights 替换旧权重；没有旧排名时拒绝继承 |
| 新建与切换会话 | `chat.html` | 每个对话独立 ID，浏览器保存页面历史，服务端按 ID 保存状态 |
| 重启恢复 | `session_store.py` | 原子写入 JSON 快照，重启后恢复对话、工具证据和排名；恢复时使用当前版本 system prompt |
| 失败回滚 | `ChatAgent.ask` | 模型或工具流程异常后回滚本轮会话、状态和新证据，保留错误审计 |
| 工具执行进度 | `web_worker.py`、`web_bridge.py` | `.status` 文件更新排队、模型调用、工具执行与失败状态，网页轮询过程中展示 |
| 本地网页服务 | `local_web.py` | 复用 worker 和同一回复协议，可接 DeepSeek 或本机可达 Qwen |
| 请求恢复 | 网页、worker | 浏览器保留 pending request ID，超时后可查询原请求，不重复提交；已有 reply 的请求不重复执行 |
| 日志与耗时 | `record` 与桥接 | session/turn/request ID、时间戳、模型输入输出、usage、工具、异常、各阶段耗时；桥接单列端到端时间 |
| 数据导出 | `scripts/export_snapshot.py` | 从冻结 prepared JSON 按固定 schema 输出 CSV，禁止直接覆盖输入快照，校验副本和哈希 |
| 自动验证 | `.github/workflows/offline.yml` | 推送或 PR 后运行单元测试、数据检查和离线数值评估；远端 CI 结果须查看实际运行 |

### 数值检查的具体取舍

本次采用保守方案：模型用定性语言解释，数值表格、排名、日期和来源由程序直接输出。模型引用 `[E1]` 等 ID；未知 ID 被拒绝。这样避免“某个数字虽然出现在证据中，却被模型安到另一个指标上”的问题，也不依赖宽松的字符串匹配。

这不能证明模型的所有文字正确。拼写出来的数词、公司原因归因、投资含义、风险描述和错误引用同一份证据中的不同概念，仍需人工解释依据评分。系统会明确显示模型解释是否降级。模型不调用工具就给出纯定性公司判断也仍是需要评估的行为，不能将后端数字检查宣称为完整事实验证。

### 记忆具体保存什么

没有关键词检索、向量数据库或后台研究 Agent。短期消息按完整轮次保留到字符预算；结构化状态保存最近五份排名、对应结果 ID 与顺序、最后排名参数及最近关注股票。工具原始结果另存为证据，前端可以显示当前计算和明确复用的旧结果。模型需要新指标时继续调用已有工具。

浏览器保存展示历史；服务端 `.state` 保存可恢复的 Agent 状态。TACC 会话文件位于该聊天作业的目录，换新作业默认是新的服务端目录，不承诺自动跨作业迁移。长会话证据仍会占用磁盘和内存，尚未实现多用户配额或过期清理。

## 4 测试和评估

在仓库根目录运行：

```bash
python3 -m unittest discover -s agent -v
python3 scripts/export_snapshot.py --check
python3 evaluation/run.py --mode offline --output evaluation/runs/offline-001
```

本地新增测试覆盖虚构数字拦截、未知证据与日期、有限修正降级、排名条件继承、失败回滚、上下文压缩、图表与原始数据一致、会话重启恢复、已完成请求不重复执行以及本地 HTTP 链路。原有财务公式和工具协议测试继续保留。

离线评估包含 30 场景、42 轮次，48 个数值检查及 18 个排名对照。参考计算不导入业务计算模块。财务来源的真实性仍依赖原数据来源核验，独立算术不是对所有财报的重新认证。

浏览器测试 `scripts/browser_smoke.cjs` 使用 Playwright 和本机 Chrome，验证概览、价格与波动率图、刷新恢复、独立会话、Top-K 追问、手机页面宽度、用户 HTML 转义与 JS 错误。它不是 Python 核心运行依赖；使用时在 Node 环境安装或提供 Playwright 模块，并先启动 `python3 agent/demo_web.py --port 18765`。可通过 `HK_TEST_URL`、`PLAYWRIGHT_MODULE`、`CHROME_PATH` 和 `HK_SCREENSHOT_DIR` 配置测试环境。

真实评估按 [evaluation/README.md](../evaluation/README.md) 执行。无工具 Baseline 通过单独普通聊天路径实现；原先 `chat_agent.py --provider deepseek` 仍是工具增强系统，不能作为 Baseline。评估分别保留模型、提示词、相同原始数据上下文、自动分数和人工评分表。不同供应商的比较只能评价整体系统。

## 5 观察到的失败与修复

原系统接受 `{"answer":"0700.HK revenue growth is 999999%."}`，即使没有调用工具。本次用明确标注的模拟模型复现，不声称真实 Qwen 曾输出该值。新增测试先返回该错误，再返回合法工具请求和不含数字的解释，确认错误数字不进入用户输出。持续出错的解释最终会被丢弃，工具结果仍能显示。

开发中还发现排名 `metric_details` 本身就是指标字典，不能按完整单股结果再次取 `metrics`。已修复所有新展示路径，并由排名回归和网页追问测试覆盖。

## 6 仍需完成的验收和范围决定

- 用户填入服务地址后，运行真实 Qwen 和 Baseline 评估；完成解释依据、历史方向和追问语义的人工评分，记录至少一个真实运行失败及处理。
- 真实 TACC 的 SDK 传输、作业恢复、服务容量、模型上下文预算和网页端到端延迟需要实测；本地模拟不作为集群成功证据。
- 原数据没有已核验的子行业分类。本分支明确支持固定科技股池中的财务条件筛选；子行业请求必须澄清或解释限制。若团队坚持行业细筛，须补有来源的行业元数据与筛选工具，并更新题集。
- 财务数据的发布日、报表期间与债务定义仍保留原有限制，不适合未经补充验证的历史回测。
- 不实现未来价格预测、自动交易或个性化投资建议；proposal 的历史走势任务已按历史指标与图表实现。
