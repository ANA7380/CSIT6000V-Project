# 股票研究 Agent 项目技术架构报告

日期：2026 年 11 月 21 日。代码基线：`661c2bd`；开发分支：`codex/complete-proposal-20261121`。本报告描述合作仓库 CSIT6000V-Project 的实际实现，供项目理解、课程汇报和后续开发使用。

> 2026-11-23 更新：当前版本已支持每次回复批量请求最多六个独立只读工具、同轮复用与连续格式错误提前停止。本报告下文的“每次一个工具”及原始 prompt 是历史描述；当前协议与测试结果见 [Tool 优化与测试报告](TOOL_OPTIMIZATION.md)，实际 prompt 以 `agent/chat_agent.py` 为准。

项目采用原生 HTML 与 JavaScript 前端、Python 标准库后端、课程 Qwen 推理服务和冻结 CSV 数据。核心是**带工具反馈循环的单 Agent 系统**：模型决定下一步调用什么工具及参数，程序校验和执行工具，把结果送回模型，直到生成可接受的解释或达到循环上限。TACC 提交、进程监督、文件传输、数值计算和页面渲染由确定性代码控制。

当前已完成 TACC 真实运行验证；它是有资源时限的课程应用部署，不是持续运行的公网多用户服务。数据为固定快照，工具按请求计算，不会自动取得最新行情。

### 1.4 服务器入口与真正的 Python 环境

[deploy/tacc/job.sh L1](/home/zyh/桌面/fin_project/CSIT6000V-Project/deploy/tacc/job.sh:1)的启动顺序是：

1. `set -euo pipefail` 和 `umask 077`，验证 SDK 和 Slurm 注入的变量。
2. `export PS1="${PS1-}"`，兼容非交互 shell 下旧 Conda 激活脚本与 `set -u` 的组合；此经验来自 MPI 作业。
3. 切到 `TACC_WORKDIR`，创建 `$TACC_USERDIR/stock-research/$SLURM_JOB_ID`。

6. 用系统 Python 启动 supervisor；由 supervisor 通过课程 runtime 启动模型和应用。
7. 将 TERM 与 INT 传给监督进程；退出时清理本次 `QWEN_RUN_DIR`。

这里必须使用 `source`：它修改当前 shell 及后续子进程的环境。单独执行 `bash activate.sh` 不会把环境改动留给父脚本。

| 本机网页桥 | 本机 Python 3.10 实测 | 标准库 HTTP 与 subprocess 调用 SDK |

公共项目根目录为 `/mnt/home/public/course-envs/CSIT6000V/project/qwen3.8-27b-v1`。应用启动命令的关键代码位于 [deploy/tacc/supervisor.py L137](/home/zyh/桌面/fin_project/CSIT6000V-Project/deploy/tacc/supervisor.py:137)：

### 1.5 Qwen 地址和服务参数

参考 [cinecontext 的 job.sh](/home/zyh/桌面/fin_project/cinecontext-qwen-e2e-fix/cinecontext-qwen-e2e/job.sh)使用 `http://127.0.0.1:42865/v1`。`127.0.0.1` 只指运行代码所在的节点；分别调度的 CPU 作业无法据此访问另一节点的 GPU 服务。因此本项目让 Qwen 与 Agent 在**同一个 GPU 作业**内运行，电脑通过 SDK 文件传输桥交互。

[deploy/tacc/supervisor.py L25](/home/zyh/桌面/fin_project/CSIT6000V-Project/deploy/tacc/supervisor.py:25)读取公共 `serve.sh`，严格核对各参数恰好匹配一次，再生成结果目录中的副本。没有直接修改公共文件。实际关键启动参数为：

```bash
-m vllm.entrypoints.openai.api_server \
  --model "$project/models/Qwen3.8-27B-AWQ-INT4" \
  --served-model-name qwen3.8-27b \
  --host 127.0.0.1 --port 42865 \
  --tensor-parallel-size 2 --language-model-only --dtype bfloat16 \
  --safetensors-load-strategy lazy \
  --gpu-memory-utilization 0.55 --max-model-len 16384 \
  --max-num-seqs 1 --enforce-eager --max-num-batched-tokens 4096 \
  --reasoning-parser qwen3 --enable-prefix-caching
```

双 GPU 采用张量并行。0.55 是 vLLM 显存预算参数，不是系统层面强制隔离的资源配额。`max-model-len=16384` 是服务的 token 上限；应用的 48000 字符上下文预算是另一种近似限制，不能简单等同于 token 数。

supervisor 先检查本机端口可绑定，再启动自己的模型进程组；轮询 `/v1/models` 并核对模型 ID，默认等待最多 1800 秒。随后 `server_entry.py` 执行真实业务检查，最后启动 worker。日志必须依次达到 `MODEL_READY`、`LIVE_SMOKE_PASSED`、`Chat ready`；作业状态为 R 或“权重加载完成”均不足以说明应用可用。

停止时先终止自己的 worker 进程组，再终止自己的模型进程组，超时强制结束；不会按全局进程名或端口清理其他作业。相关代码见 [deploy/tacc/supervisor.py L73](/home/zyh/桌面/fin_project/CSIT6000V-Project/deploy/tacc/supervisor.py:73)和 [deploy/tacc/supervisor.py L194](/home/zyh/桌面/fin_project/CSIT6000V-Project/deploy/tacc/supervisor.py:194)。

### 2.3 后端并非单一 HTTP 服务

服务器部署把后端分成两部分。电脑上的 [agent/web_bridge.py L26](/home/zyh/桌面/fin_project/CSIT6000V-Project/agent/web_bridge.py:26)运行标准库 `ThreadingHTTPServer`，提供浏览器接口；计算节点的 [agent/web_worker.py L53](/home/zyh/桌面/fin_project/CSIT6000V-Project/agent/web_worker.py:53)扫描私有共享目录中的请求文件，并串行处理 Agent 任务。

| 接口 | 请求和响应 | 具体代码 |
|---|---|---|
| GET `/` | 返回从服务器 namespace 下载的 chat.html | `Bridge.main()` 下载页面；`do_GET()` 返回内存中的页面 |
| POST `/ask` | 入参 `{session, question}`；成功 HTTP 202 `{turn: request_id}` | [agent/web_bridge.py L64](/home/zyh/桌面/fin_project/CSIT6000V-Project/agent/web_bridge.py:64) |
| GET `/reply/ID` | 未完成 HTTP 202 `{event,...}`；完成 HTTP 200 结构化结果或业务 error | [agent/web_bridge.py L40](/home/zyh/桌面/fin_project/CSIT6000V-Project/agent/web_bridge.py:40) |

网页桥检查 Host、Origin、Content-Type、请求长度和 32 位十六进制会话 ID；SDK 传输异常返回 502。完成请求本身可以返回 HTTP 200 且正文带 `error`，所以前端不能只靠状态码判断业务成功。

### 2.4 单次问题的时序

![单次问题传输时序](/home/zyh/桌面/fin_project/CSIT6000V-Project/docs/architecture/request-sequence.svg)

对应代码和数据变化如下：

1. 浏览器提交 `{session, question}`。桥产生独立 request ID，开始端到端计时。
2. 桥先上传 `ID.request`，内容为问题；成功后上传 `ID.ask` 提交标记，例如 `{"protocol":2,"payload":"ID.request"}`。见 [agent/web_bridge.py L81](/home/zyh/桌面/fin_project/CSIT6000V-Project/agent/web_bridge.py:81)。这避免 worker 读取上传一半的 JSON。
3. worker 每秒扫描一次 `.ask`，校验 payload 名必须等于当前 ID 的 `.request`，不能指定其他路径；已有 `.reply` 的请求不再执行。见 [agent/web_worker.py L12](/home/zyh/桌面/fin_project/CSIT6000V-Project/agent/web_worker.py:12)。
4. 以 session 查找 `sessions` 中的 ChatAgent；第一次加载该会话时恢复 `.state`。随后执行 `agent.ask(question)`。
5. 每个模型或工具阶段通过 `record()` 的 progress 回调写入 `ID.status`；浏览器查询时由桥下载并返回。这里是状态轮询，不是 token 流式输出。
6. Agent 生成 `last_response`，worker 保存会话快照，再原子写 `ID.reply`，删除 `.ask` 和 `.request`。
7. 桥下载 `.reply`，附加 `end_to_end_ms`；前端分开渲染 explanation、工具证据、图表和时间。

完成回复中有 `answer`、`explanation`、`evidence`、`state`、`turn_id`、`request_id`、`duration_ms`、`fallback`，桥另加 `end_to_end_ms`。其中 worker 的 `answer` 带确定性文本结果附录，`explanation` 是单独的模型解释；网页优先使用 explanation，避免重复显示附录。

两阶段文件提交避免半文件读取，已有回复避免已完成请求重复计算；但“执行结束、持久化回复之前崩溃”仍可能导致重启后重算，并不是数据库事务意义上的 exactly-once 协议。

### 2.5 会话和本地运行方式

[agent/session_store.py L7](/home/zyh/桌面/fin_project/CSIT6000V-Project/agent/session_store.py:7)用临时文件加原子 replace 保存私有 JSON，权限设为 0600。快照包括 messages、state、evidence、next_evidence；恢复时始终使用当前代码中的 system prompt，不信任旧快照的指令。审计 JSONL 还保存模型调用、工具参数、结果、耗时和错误；不记录 API 密钥，但包含用户问题及业务数据。

前端 localStorage 和服务器 `.state` 的职责不同：前者恢复界面和 session ID，后者恢复 Agent 历史与证据。换浏览器或清空本地存储后，服务器状态不会自动显示为完整的可检索会话列表。

## 3 Agent 架构与节点职责

### 3.1 架构结论

`ChatAgent` 是单模型驱动的、应用管理工具调用的有界 Agent loop，可描述为 ReAct 风格的“行动—观察—再行动”，但并没有输出或保存显式 Thought 推理链。当前 Qwen 请求设置 `enable_thinking: false`。

判断它是 Agent 的依据不是使用了什么框架，而是 [agent/chat_agent.py L173](/home/zyh/桌面/fin_project/CSIT6000V-Project/agent/chat_agent.py:173)中的循环：模型看到用户问题和之前的工具反馈后，自主返回 `tool` 或 `answer`；执行路径和调用次数可以随问题变化。普通概念问题可直接答复，公司概览可先找股票再查指标和价格，排名追问可再次调用排名工具。它不是固定的“检索一次—计算一次—总结一次”串行链。

自主性受到明确约束：工具只有六个、一次模型调用最多执行一个动作、最多 12 次模型调用，不允许 shell、代码执行、在线搜索或任意文件访问。外层启动流程与工具内部算法本身仍是确定性 workflow。

当前也没有多个 Agent、独立 planner、独立 critic、LangGraph 状态图、向量数据库或 RAG 检索器。类名 `TickerAgent` 实际是确定性计算引擎，不是第二个 LLM Agent。校验器是 Python 函数，不是另一个“评审模型”。

### 3.3 状态记忆与上下文管理

`state` 在 [agent/chat_agent.py L89](/home/zyh/桌面/fin_project/CSIT6000V-Project/agent/chat_agent.py:89)初始化：

```json
{
  "ranking_history": [],
  "last_ranking_request": null,
  "focused_symbols": []
}
```

排名成功后保存最近有效参数和最近 5 次排名句柄；单股工具成功后保留最近 10 个关注股票。`_context()` 再加入最近 40 条证据的 ID、工具名和参数，帮助模型理解追问引用。它不是向量记忆：完整证据仍在对象和 JSON 快照中，近期对话则按完整用户轮次裁剪。

上下文默认预算为 48000 字符。裁剪时不切断当前轮次中的工具请求与反馈；若当前请求本身仍过大，明确失败。每次将新的 `SESSION_STATE` 合并到**唯一首条 system 消息**，存储时继续保留静态 system，避免把动态状态反复累积。

排名偏好继承是代码保障的，而非单靠模型记住：模型给 `reuse_previous: true` 时，`dispatch()` 执行 `dict(last_ranking_request, **args)`，只覆盖新字段。`filters: {}` 清空旧筛选；新的 weights 整体替换旧 weights。若模型不发 reuse_previous，程序不会自动替它继承，真实追问能力仍依赖模型正确理解并选择此参数。

### 3.4 模型协议和证据约束

Qwen 使用 OpenAI 兼容聊天 HTTP 接口，但没有传原生 `tools` 或 `tool_choice` 参数。工具目录被拼入 system 文本，模型在普通 content 中生成 JSON；应用负责解析和执行。工具反馈用 `role: user` 加 `TOOL_RESULT` 前缀传入，并非原生 `role: tool` 消息。

`parse_action()`可去掉外围代码围栏；工具 JSON 后即使带过早回答，也只恢复并执行合法的前导工具请求，不采用尾随解释。最终 answer 则必须是单个完整 JSON，不能附加多余文本。这种兼容处理不意味着任意混合输出都会被接受。

`validate_answer()`要求引用存在；本轮有新工具结果时要求有引用，禁止额外数字字符和 URL，允许已知股票代码、指标名及 E 编号。`fifty/200 crossover` 只在证据存在相关交叉字段时放行。表格数值、单位、日期、来源和曲线始终由工具结构化结果渲染。

这一机制减少数字幻觉，但不证明语义正确：英文拼写数字、公司定性判断、新闻因果和引用是否真正支持句子，仍不能被字符规则完整验证。另外，概念问题允许不调用工具；当前代码没有独立意图分类器强制所有数据型问题执行工具，需通过模型 prompt、测试和人工审查补足这一边界。

### 5.2 list_tickers 名称消歧

从 `TickerAgent.snapshot` 构造全部支持股票的名称映射。模型拿到表后自行把“腾讯”等名称对应到代码，再调用后续工具；这是模型读字典后的选择，不是单独实现了模糊搜索引擎或名称向量检索。

### 5.3 ticker_metrics 核心财务指标

`TickerAgent.__init__()`载入三份 CSV，`run()`从单行快照取财务输入，从价格表选窗口，代码见 [agent/agent.py L27](/home/zyh/桌面/fin_project/CSIT6000V-Project/agent/agent.py:27)。

| 指标 | 公式与口径 | 异常处理 |
|---|---|---|
| 营收增长率 | `(本期营收 / 同比营收 - 1) × 100` | 分母须为正；检查上年同月、日期差不超过一天，避免把非同比期间比较 |
| 净利润率 | `净利润 / 营收 × 100` | 缺值或非正营收返回 unavailable；保留利润口径说明 |
| 债务权益比 | `总债务 / 股东权益`，单位 x | 分母非正不硬算；资产负债表日期和币种独立保留 |
| 年化历史波动率 | `sample_stdev(log(Pt/Pt-1)) × sqrt(252) × 100` | window 个收益率需要 window+1 个复权价格；少于 3 个价格、重复日期、非正价格不可用；能算但不足请求窗口则 short_history |

短历史波动率可以展示实际使用的数据量，但排名不会把要求完整窗口的不足历史值当成合格值。数据空白不会按 0 填充；财务期间和价格窗口不会混称为同一日期。

### 5.4 financial_trends 可比年度趋势

只使用 `annual...` 且 `period_type == '12M'` 的供应商观察行，按 symbol、年度结束日和币种精确匹配；同一个匹配键不是恰好一行则不使用。避免把季度发行人补充行与年度供应商数据拼成一次增长计算。

- 债务与权益增长：`(本年值 / 上年值 - 1) × 100`，上年值须为正。
- 利润率变化：`本年度净利润/营收 × 100 - 上年度净利润/营收 × 100`，单位为百分点。
- ROE：`年度净利润 / ((期初权益 + 期末权益)/2) × 100`，期初和期末权益均须为正。

每个指标寻找自身最新可用的年度组合，所以不同指标可能对应不同年度，且可能早于核心快照的收入期。找不到可比输入时返回 null 和 reason，不进行季度年化，也不把缺数补为零。

### 5.5 price_analysis 历史价格与图表

价格使用 adjusted_close，成交量指标例外。`positive_prices()`要求整段输入没有重复日期和非正复权价，不插值。具体算法如下：

| 子指标 | 实现方式 |
|---|---|
| 1/3/6/12 月收益 | 按日历月回退，选择目标日或之前最后一个交易日；不是固定 21/63 个交易日替代 |
| SMA20/50/200 | 对最新 N 个复权价格求均值；完整历史计算后再截取显示段，防止显示窗口不足造成错误均线 |
| RSI14 | 先用前 14 个价格变化的平均涨跌初始化，再按 Wilder 公式递推；完全横盘约定 RSI=50，无跌幅但有涨幅时为 100 |
| MACD12/26/9 | EMA12−EMA26；EMA 用 SMA 种子初始化，signal 是 MACD 的 EMA9，另给 histogram |
| 最大回撤 | 在最近 window+1 个价格中维护运行峰值，求最小 `(当前价/运行峰值−1)×100`，记录峰谷日期 |
| 滚动年化波动率 | 每点使用 rolling_window 个对数收益率；保留最近 window 个滚动点 |
| 成交量比 | 最新成交量 / **此前** 20 个交易日平均量，不把当天放入基线 |
| 均线状态与交叉 | 判断当前价格和均线位置；50/200 交叉比较今天与昨天均线差的符号，不能只看当前大小关系 |

两个窗口必须区分：`window=60`控制最大回撤区间、最多 61 个价格图点和最多 60 个滚动波动率图点；`rolling_window=20`控制每个波动率点的估计跨度。单一 SMA、RSI、MACD 使用可用完整历史计算，不会统一改成 60 日定义。

字段 `latest_50_200_crossover` 检查的是最新一个交易区间有没有交叉，不搜索历史上最近一次交叉的日期。若最新没有发生交叉，即便更早出现过，也返回 none。历史不足 201 个价格时不产生这个字段。

### 5.6 stock_correlation 同区间相关性

两只股票分别形成 `(起始日期, 结束日期) → 对数收益率` 映射，取区间键的交集，再选最近 window 个。这样不会把一只股票停牌后的多日收益与另一只的一日收益相配。

计算 Pearson 系数：`Σ((xi−均值x)(yi−均值y)) / sqrt(Σ(xi−均值x)² × Σ(yi−均值y)²)`。少于两个匹配区间或收益率恒定导致分母为零时不可用；不足完整窗口时标 short_history。该工具不是市场 beta，也没有接入市场基准收益率。

### 5.7 rank_stocks 筛选与可解释评分

先执行强制筛选，再在剩余候选集合内部归一评分，处理步骤见 [agent/analysis_tools.py L241](/home/zyh/桌面/fin_project/CSIT6000V-Project/agent/analysis_tools.py:241)：

1. 检查 weights 非空、非负且总和为正，值须有限；检查 filters 仅含四项核心指标的 min/max，最小值不能大于最大值。
2. 对 30 只股票计算核心指标。所需字段为正权重指标与筛选指标的并集；缺失或状态不为 ok 时排除，随后应用强制阈值。
3. 在合格集合内，对每项指标计算带并列中位名次的百分位分数。若有 n 个候选，`r = 小于当前值的数量 + (等于当前值的数量−1)/2`，`p = 100r/(n−1)`；只有一个候选时为 50。
4. 营收增长和利润率使用 p；债务和波动率使用 `100−p`，令有利方向统一为高分。
5. 正权重归一后计算 `score = Σ(weight × favorable_percentile)`；降序排列，同分按股票代码排序，返回 top_k。

返回每只股票原始四指标、percentile_scores、contributions、score、rank，及全体 excluded 原因。它是样本内描述性评分，不是预测收益或概率。改变筛选条件会改变候选总体，分数因此可能改变；跨不同筛选总体不能把分数当作绝对可比值。筛选中 10 表示 10%，债务比 0.5 表示 0.5x，代码和 prompt 均明确区分。
