# TACC 服务器部署与运行指南

合作项目在课程 TACC 计算节点上运行 Qwen 和股票 Agent，通过已配置账户的 tcloud SDK 与本机浏览器交互。新增部署入口位于 `deploy/tacc/`，操作工具是 `scripts/tacc.py`。实现依据包括本地 `cinecontext-qwen-e2e-fix/cinecontext-qwen-e2e/job.sh`、mpi-assignment 的实际提交记录，以及服务器公开的 Project 激活和模型服务脚本。

## 1 采用同一作业运行模型和 Agent

参考脚本中的地址是 `http://127.0.0.1:42865/v1`。`127.0.0.1` 指当前计算节点自身，不是本机电脑，也不代表另外一个 CPU 作业的节点。不同作业分别调度后，即使端口相同，也可能访问不到对方。

本部署在一个申请两块 GPU 的作业中启动：

```text
本机网页 → 本机 web_bridge → tcloud 认证文件传输
                             ↓
课程 GPU 作业
  web_worker → ChatAgent → 127.0.0.1:42865/v1 → Qwen
      ↓              ↓
  持久会话       财务计算与固定 CSV
```

模型保持节点内回环绑定。没有为公网开放模型端口，也不需要从笔记本访问计算节点内部 IP。课程原来的双作业方式仍保留，可用于明确绑定非回环可达地址的独立模型服务；不要把新方案的回环地址填给另一台节点上的旧客户端。

## 2 首次检查 SDK 和课程环境

本机已存在 mpi-assignment 的 SDK，可直接复用：

```bash
source /home/zyh/桌面/mpi-assignment/env.sh
cd /home/zyh/桌面/fin_project/CSIT6000V-Project
python3 scripts/tacc.py preflight
```

在其他电脑上，先按课程说明配置 tcloud 账户和对应私钥，然后使用自己的 SDK 路径：

```bash
export TCLOUD_BIN=/实际位置/tcloud
python3 scripts/tacc.py preflight
```

当前电脑的工具会优先查找参数 `--sdk`、环境变量 `TCLOUD_BIN`、PATH，最后尝试旁边 mpi-assignment 的已安装 SDK。不会读取或上传私钥内容到作业目录。

若账户还没有 `proxy` 环境入口，执行课程配套注册脚本：

```bash
bash agent/setup-sdk-account.sh
```

本次已为当前服务器账户执行注册并确认成功。它注册共享空入口，实际程序仍通过 `/mnt/home/public/course-envs/CSIT6000V/project/activate.sh` 使用公共 Qwen 环境，不向公共环境安装包。不要更新公共 Conda 或自行复制模型权重。

## 3 一条命令提交服务器应用

在合作仓库根目录执行：

```bash
python3 scripts/tacc.py submit --mode web --namespace hk-research --minutes 60
```

也可以沿用 `agent/` 目录下的 `bash submit-web.sh`；它现在默认调用同作业部署。旧的独立模型 CPU 模式需明确加 `--external-model`。

程序会生成 `var/tacc/stock-research-时间戳-随机后缀/`，仅包含应用代码、三份 CSV、必要的部署脚本与清单，然后在这个隔离目录执行 `tcloud submit`。目录名每次不同，避免 SDK 重用同名 WORKDIR 时覆盖正在运行的旧版本。源码仓库、API 密钥、个人日志和 SSH 文件不在上传清单中。

记录输出的真实 `JOB_ID`。下文 `你的JOB_ID` 都需替换成这个数字：

```bash
python3 scripts/tacc.py status 你的JOB_ID
```

排队时还没有日志是正常情况，不要重复提交同一任务。运行后日志先出现 `MODEL_READY`，再出现 `LIVE_SMOKE_PASSED`，最后才有 `Chat ready`。只有最后一步完成，网页应用才可使用。

`--mode diagnostic --minutes 5` 只申请两个 CPU，在课程真实 Python 环境运行完整测试，不请求 GPU 或模型。

`--mode smoke --minutes 30` 只运行真实模型检查，通过后退出并释放 GPU。`--skip-smoke` 可跳过检查进入网页 worker，但不表示该次部署已通过真实模型验收。建议初次部署保留检查。

## 4 在本机打开服务器网页

首次模型启动会包含公共 Python 及 GPU 引擎初始化。本次首次运行中，引擎 profile 与预热约耗时 370 秒；权重已加载不等于接口已就绪。启动日志中临时出现共享内存广播等待提示也不能单独判定失败，应结合后续日志与就绪探测。

等待 `Chat ready` 后执行：

```bash
python3 scripts/tacc.py bridge 你的JOB_ID
```

浏览器打开打印的地址，默认 `http://127.0.0.1:8765/`。这里的 8765 是本机网页桥端口，42865 是计算节点内模型端口，二者作用不同。

若本机 8765 已占用：

```bash
python3 scripts/tacc.py bridge 你的JOB_ID --port 8766
```

网页静态内容、对话状态、真实模型推理和所有财务工具运行在服务器；本机桥仅负责展示页面和通过 SDK 上传、查询请求。tcloud 文件传输增加端到端延迟，不能将浏览器等待时间全都解释为模型推理时间。

建议先输入：

- `Show all four metrics for 0700.HK using 60 daily returns for volatility.`
- `Rank the top 3 stocks using net profit margin only, requiring margin at least 10%.`
- 追问 `Keep the same filters and weights, but show the top 5.`
- `展示 0700.HK 的历史价格、均线和波动率图，不预测未来。`

## 5 地址和服务参数在哪里设置

**新同作业部署默认不需要手填模型地址。** supervisor 自动设置 `QWEN_BASE_URL=http://127.0.0.1:42865/v1` 并传给同一作业的 Agent。

若该端口在分配到的节点已占用，可以在提交时换端口：

```bash
python3 scripts/tacc.py submit --mode web --namespace hk-research --port 42866
```

启动前先检查端口占用；不会为了腾出端口终止其他服务。程序在自己的结果目录生成服务启动副本，只修改这个副本，原课程 `serve.sh` 保持不变。修改前严格核对参考参数是否各出现一次，公共脚本变化时明确失败，避免悄悄应用错误替换。

默认参数沿用你提供的实验脚本：两块可见 GPU、模型上下文 16384、并发 1、GPU 显存比例 0.55、lazy 加载、eager 执行。实际 GPU 索引从作业可见设备中取得；若不是恰好两块，则停止并提示，而不猜测可用 GPU。

提交包中的 `deployment.json` 保存这些参数。可以先 `package`、检查并修改生成目录中的配置，再从该目录手动 `tcloud submit`。服务参数影响资源需求与模型可接受的上下文，改动后应重新做真实检查。

对于已有的独立远端模型服务，旧客户端依然支持 `agent/server-url.txt`、`QWEN_BASE_URL` 或 `--base-url`；那一条地址必须从运行客户端的服务器节点实际可达。

## 6 结果保存和会话恢复

每次作业的结果保存于：

```text
TACC_USERDIR/stock-research/JOB_ID/
  deployment.json          实际部署参数和节点内地址
  status.json              启动 运行 就绪 结束或失败状态
  model.log                vLLM 启动及推理日志
  runtime-samples.jsonl      启动时本服务进程组和 GPU 显存采样
  live-smoke.json          真实模型检查结果
  live-smoke-audit.jsonl    完整模型请求 工具证据和耗时
  connection.json          网页桥发现持久会话目录的清单
  error.json               supervisor 错误 如有
  agent-error.json          Agent 检查或 worker 错误 如有
```

下载本次结果和 Slurm 日志：

```bash
python3 scripts/tacc.py download 你的JOB_ID
```

本地目标为 `var/tacc-results/JOB_ID/`。对已完成的真实检查，可独立复核返回数值、排名和图表长度：

```bash
python3 scripts/check_server_results.py var/tacc-results/你的JOB_ID/live-smoke.json
```

它使用独立计算参考，不评分模型定性解释。WORKDIR 仅用于本次运行代码；结果、状态和会话显式放在 USERDIR，不依赖平台自动搬运。

使用 `--namespace hk-research` 时，会话存放在 `TACC_USERDIR/stock-chat/hk-research/`。后续新作业使用相同 namespace，可以从私有 JSON 快照继续恢复；本机网页的 conversation ID 也要保留。同一 namespace 同时只允许一个 worker，文件锁会拒绝第二个，避免两个作业同时改同一会话。浏览器桥通过本次 `connection.json` 找到实际目录。

请求采用两步提交：先上传 `.request` 数据，成功后才上传 `.ask` 提交标记。worker 只在标记出现后读取数据，避免把正在上传的半份 JSON 当作完整问题。已完成请求不会重复执行。旧格式本地请求仍兼容。

## 7 停止服务和释放资源

完成使用后执行：

```bash
python3 scripts/tacc.py stop 你的JOB_ID
```

只停止自己这次提交的作业。supervisor 会向自己启动的模型和 worker 进程组转发停止信号，超时再强制退出，最后清理课程激活产生的本次临时 runtime。它不会按全局端口或全局进程名杀进程。

作业到达设置时限也会结束。本机桥按 Ctrl+C 只关闭本机展示桥，不会自动取消服务器 GPU 作业，因此仍需执行 stop。namespace 会话和按 Job ID 保存的结果继续保留。

## 8 常见故障

| 现象 | 检查方法 |
|---|---|
| PD 或 Priority 或 Resources | 作业尚在排队，查看同一个 Job ID，不要重复提交 |
| proxy 激活失败 | 用配套 `agent/setup-sdk-account.sh` 注册入口，确认 SDK 使用本人的账户 |
| GPU 可见数不是两块 | 查看该作业日志及 `gpus.csv`，不要覆盖调度器资源限制 |
| 模型迟迟未就绪 | 下载 `model.log`，检查权重加载、显存和课程 runtime；启动等待默认最多 1800 秒，与原股票实验一致 |
| 42865 已占用 | 用 `--port` 重新提交到另一个端口，不终止未知服务 |
| HTTP 400 提示 system 位置错误 | 使用本分支修复版，规则和会话状态必须合并在唯一的首条 system 消息中 |
| live-smoke 失败 | 下载 `live-smoke-audit.jsonl` 和 `agent-error.json`；检查真实工具选择、格式、上下文或继承条件 |
| 有 MODEL_READY 但没有 Chat ready | 检查尚未完成或已失败，不能提前使用 bridge |
| namespace 被占用 | 停止自己的旧作业，或换一个 namespace，不并发写同一会话 |
| 本机连接不到计算节点地址 | 使用 SDK bridge；节点内回环地址本来就不能供笔记本直接访问 |
| SDK 输出错误但退出码为零 | 新操作工具额外识别 `[Tcloud Error]` 等错误标记，不把零退出码当作成功 |
| 网页请求超时 | 检查作业状态，继续查询原 request ID；不要以重新发送代替查询 |

真实运行结果和本次 Job ID 记录在 `docs/服务器部署实测记录.md`。完整的课程最终评估仍需独立运行题集和无工具 Baseline；部署检查通过不等于全部自然语言任务均通过。
